Sites Dinâmicos Sem Mistério: do JavaScript Básico ao React

Guia direto para a prova (Prof. Guilherme Assunção): só o básico de cada um dos 11 tópicos do guia oficial, em português simples, código traduzido linha por linha, 3 labs interativos e 20 questões comentadas.

1. O Papel de Cada Peça na Web + Variáveis (Cap. 01)

Antes de ler código, lembre do trio básico de qualquer site:

🧱 HTML (Estrutura)

É o esqueleto da página: títulos, textos, botões e formulários.

🎨 CSS (Aparência)

É a roupa e a pintura: cores, fontes, tamanhos e espaçamentos.

⚡ JavaScript (Comportamento)

É o cérebro: faz contas, toma decisões e reage quando o usuário clica ou digita.

Variáveis: const vs let e os 3 tipos básicos

Uma variável é uma caixinha com nome que guarda um valor na memória.

  • const: trava o vínculo — depois que você coloca o valor, não pode trocar (reatribuir) por outro.
  • let: deixa trocar o valor depois (ex.: contador de acessos que vai subindo).
  • Tipos mais comuns: string (texto entre aspas), number (número) e boolean (true ou false).
  • typeof: operador que responde qual é o tipo daquele valor.
const linguagem = "JavaScript"; // string (texto) — não muda
let acessos = 2;                // number (número) — pode mudar depois
acessos = acessos + 1;          // agora acessos vale 3

console.log(typeof linguagem);  // mostra: "string"
console.log(typeof acessos);    // mostra: "number"
⚠️
Pegadinha nº 1 da Prova: Texto e Número NÃO são a mesma coisa!

Tudo o que o usuário digita num campo HTML (input) ou no prompt() chega para o JavaScript como texto (string)!
Se você usar o sinal + com texto, o JS gruda (concatena) em vez de somar: "6" + 2 vira "62"!
Solução: converta com Number(...) antes de fazer conta! 

const quantidade = "6";              // veio de um campo → é TEXTO ("6")
const convertida = Number(quantidade); // agora virou NÚMERO (6)
console.log(convertida * 2);           // mostra: 12

Contas, ===, if e for

  • Contas: + (soma), - (subtrai), * (multiplica), / (divide) e % (resto da divisão — ótimo para saber se é par!).
  • === (igualdade estrita): compara valor E tipo sem adivinhar. Ex.: 5 === "5" é false (número não é texto).
  • if: só executa o bloco se a condição for verdadeira.
  • for: repete um bloco várias vezes seguindo um contador.
// Repete numero de 1 até 5, somando 1 a cada volta
for (let numero = 1; numero <= 5; numero++) {
  if (numero % 2 === 0) {           // se o resto da divisão por 2 for exatamente 0...
    console.log("Par:", numero);    // ...imprime os pares: 2 e 4
  }
}

2. Manipulação de Arrays (Cap. 02)

Um array é uma lista que guarda vários itens dentro de uma mesma variável, entre colchetes [ ]. Pense em uma prateleira numerada onde a primeira vaga sempre é a 0! 

const produtos = ["livro", "caderno", "lapis"];
// índices:         0         1          2

console.log(produtos[1]);     // mostra "caderno" (índice 1 é o 2º item!)
console.log(produtos.length); // mostra 3 (quantidade total de itens)
⚠️
Pegadinha Clássica de Array: length × Último Índice

Se um array tem 3 itens (length === 3), os índices são 0, 1, 2.
Logo, length não é o índice do último item! O último índice é sempre length - 1.

Os 3 métodos que você precisa diferenciar na prova

Método O que ele faz? Altera o array original? O que devolve?
push(item) Coloca um item novo no final da lista. Sim! Muda o array original. O novo tamanho (length) da lista.
filter(fn) Testa cada item e pega só os que passam na condição. Não! Preserva o original. Um novo array (pode ter menos itens).
map(fn) Transforma/converte cada item (ex.: aplicar taxa). Não! Preserva o original. Um novo array (sempre do mesmo tamanho). 
const precos = [15, 40, 22, 60];

// filter: escolhe só os maiores que 25 (devolve NOVO array: [40, 60])
const altos = precos.filter(function(p) {
  return p > 25;
});

// map: aumenta 5% em cada preço (devolve NOVO array: [15.75, 42, 23.1, 63])
const comTaxa = precos.map(function(p) {
  return p * 1.05;
});

// push: adiciona 18 no FINAL do próprio array precos
precos.push(18);
📘
O que é um Callback?

No código acima, aquela função passada dentro de filter(...) e map(...) se chama callback (uma função entregue como argumento para o método rodar em cada item). No filter, o callback responde sim ou não (true/false); no map, ele devolve o novo valor transformado.

1. Formulários e Eventos com addEventListener (Cap. 03)

Um site fica dinâmico quando reage ao que a pessoa faz (clicar, digitar, apertar tecla, enviar formulário). Cada ação dessas é um evento.

No HTML, um formulário básico usa 4 tags amigas: <form> (agrupa os campos), <label> (etiqueta do campo), <input> (caixinha onde se digita) e <button> (botão que envia ou aciona algo).

Como o JS "escuta" um elemento?

Primeiro você acha o elemento na página com document.querySelector(...) e depois instala um "ouvido" com addEventListener("evento", funcao). 

// Acha o elemento cujo id="busca" (o # significa ID; o . significa classe)
const campo = document.querySelector("#busca");

// Toda vez que o texto mudar ("input"), executa a função:
campo.addEventListener("input", function() {
  console.log("Texto atual:", campo.value);
});
Evento Quando dispara? Para que serve?
click Quando clica em um elemento (botão, cartão, etc.). Executar uma ação na tela.
input A cada alteração no valor de um campo. Acompanhar a digitação em tempo real.
submit Quando tentam enviar o formulário (<form>). Validar e processar os dados digitados.
keydown Quando uma tecla do teclado é pressionada. Atalhos e interações pelo teclado.

Segurando o envio padrão: e.preventDefault()

Por padrão, quando um <form> é enviado (submit), o navegador tenta recarregar/enviar a página. Para o JavaScript assumir o controle sem recarregar tudo, chamamos e.preventDefault()! 

const formulario = document.querySelector("#contato");

formulario.addEventListener("submit", function(e) {
  e.preventDefault(); // trava o recarregamento padrão do navegador
  console.log("Tratando os dados do formulario");
});
⚠️
Pegadinha da Prova sobre preventDefault()

e.preventDefault() NÃO valida campos, NÃO limpa o formulário e NÃO envia dados sozinho! Ele faz uma única coisa: impede a ação padrão do navegador (se o evento for cancelável). Todo o resto precisa ser escrito no seu código.

2. Manipulação do DOM: textContent × innerHTML (Cap. 04)

O DOM (Document Object Model) é o mapa vivo que transforma as tags HTML em objetos que o JavaScript consegue ler e alterar na hora.

🧩
Não confunda os 3 nomes!

HTML = texto/código do arquivo.
DOM = representação viva da página na memória que o JS manipula.
textContent / innerHTML = propriedades usadas para trocar o conteúdo de um elemento selecionado.

Lembre-se: document.querySelector() sempre devolve apenas o primeiro elemento que combina com o seletor (#id ou .classe). E atribuir um novo valor a textContent ou innerHTML substitui tudo o que tinha dentro daquele elemento antes!

✅ textContent (Texto Puro)

Escreve o texto literalmente, sem interpretar tags HTML.
Se você mandar "<em>Oi</em>", aparece escrito <em>Oi</em> na tela.
Mais seguro para dados digitados pelo usuário!

🏷️ innerHTML (HTML Interpretado)

Interpreta as tags HTML da string e cria elementos de verdade.
Se você mandar "<em>Novidades</em>", aparece Novidades em itálico.
Cuidado: perigoso usar com texto digitado por usuário ou fonte não confiável! 

const mensagem = document.querySelector("#mensagem");
mensagem.textContent = "O registro foi recebido."; // só texto literal (seguro)

const titulo = document.querySelector("#titulo");
titulo.innerHTML = "<em>Novidades</em>";       // interpreta a tag <em>

3. Template Strings e Validação de Campos (Cap. 05)

Template Strings são textos escritos com crases (`...`) em vez de aspas. Com elas, você encaixa variáveis direto dentro do texto usando ${...} (interpolação) e pode até quebrar linhas sem precisar ficar somando +! 

const atividade = "laboratorio";
const encontros = 3;
// Repare nas CRASES (` `) e no ${variavel} dentro delas:
const aviso = `Atividade: ${atividade} | Dias: ${encontros}`;
console.log(aviso); // "Atividade: laboratorio | Dias: 3"

Kit básico de limpeza e checagem de Strings

Recurso Tipo Para que serve?
trim() Método (usa ()) Remove espaços sobrando no início e no fim do texto.
length Propriedade (SEM ()!) Informa quantos caracteres a string tem.
includes("x") Método Diz se o texto contém aquele pedaço (true/false).
replace("a", "b") Método Troca uma ocorrência de texto por outra.
startsWith() / endsWith() Método Verifica se começa ou termina com determinado trecho.
toUpperCase() / toLowerCase() Método Converte tudo para MAIÚSCULAS ou minúsculas. 
const entrada = "  Projeto Web  ";
const normalizada = entrada.trim();           // "Projeto Web" (tirou espaços das pontas)
const padrao = normalizada.toLowerCase();     // "projeto web" (tudo minúsculo)
console.log(padrao.length);                   // 11 (repare: length SEM parênteses!)
⚠️
2 Cuidados de Prova em Strings e Validação

1. length é propriedade (sem ()), diferente de trim() e toLowerCase() que são métodos (com ()).
2. Só tirar espaços (trim()) ou contar caracteres (length) ajuda, mas não garante sozinho que um e-mail ou documento complexo seja válido — a validação precisa refletir uma regra do sistema.

1. localStorage: Memória Persistente no Navegador (Cap. 06)

Normalmente, quando você fecha ou atualiza a página, as variáveis do JS somem. O localStorage é uma gavetinha do próprio navegador que guarda pares de chave e valor e não apaga mesmo depois de fechar a aba ou o navegador (no uso normal).

Comando O que faz? Detalhe importante
localStorage.setItem("chave", "valor") Salva um valor ligado a uma chave. Se a chave já existir, substitui o valor antigo.
localStorage.getItem("chave") Lê o valor guardado naquela chave. Devolve null se a chave não existir.
localStorage.removeItem("chave") Apaga só o item daquela chave. Os outros itens continuam salvos.
localStorage.clear() Apaga tudo daquela origem/site. Limpa o localStorage inteiro do site. 
// Salvando e lendo uma preferência simples (texto)
localStorage.setItem("layout", "compacto");
const preferencia = localStorage.getItem("layout"); // tem que usar a MESMA chave!
console.log(preferencia);                           // mostra: "compacto"
⚠️
As 2 Grandes Pegadinhas do localStorage

1. Só guarda texto (string)! Se você tentar salvar um objeto ou array direto, vira bagunça ("[object Object]"). Para guardar objetos/arrays, precisa converter para texto com JSON.stringify() antes!
2. NÃO é banco de dados seguro! Não substitui um banco de dados no servidor e nunca deve guardar senhas ou dados sensíveis — serve só para preferências locais e configurações simples.

2. JSON: Formato de Texto para Trocar Dados (Cap. 08)

JSON significa JavaScript Object Notation. Apesar do nome lembrar JavaScript, ele é um formato de texto leve que quase toda linguagem entende (Python, Java, PHP, JavaScript...). É o "envelope padrão" usado em APIs, localStorage, arquivos de configuração e Node.js. 

{
  "evento": "Semana de Tecnologia",
  "participantes": 42,
  "aberto": true,
  "salas": ["A1", "B2"]
}

As 4 Regras de Ouro do JSON Válido (Cai Muito na Prova!)

✅ O que TEM que ter

  • Aspas duplas ("...") obrigatórias em TODAS as chaves e textos.
  • Só aceita 6 tipos: string, number, boolean, null, array e object.

❌ O que é PROIBIDO

  • Vírgula extra depois do último item de objeto ou array.
  • Comentários (// ou /* */) e funções JS.
  • Aspas simples ('texto') ou chave sem aspas.

Os 2 comandos que convertem ida e volta

Método Direção da conversão Pense assim
JSON.stringify(valor) Objeto/Array JS → String JSON Empacota em texto para salvar ou enviar pela rede.
JSON.parse(texto) String JSON → Objeto/Array JS Desempacota o texto para usar como objeto no código. 
const configuracao = { fonte: "media", alertas: false };

// 1. Transforma objeto JS em texto JSON para poder guardar no localStorage
const texto = JSON.stringify(configuracao);
localStorage.setItem("config", texto);

// 2. Depois, lê o texto e transforma de volta em objeto JS
const salvo = localStorage.getItem("config");
const recuperado = JSON.parse(salvo); // cuidado: se o texto JSON for inválido, dá erro!
📘
JSON ≠ Objeto JS na Memória

Um JSON é apenas uma string (texto) formatada. Você não consegue fazer texto.fonte antes de passar pelo JSON.parse(texto)! E quando o texto vem de fora (API, usuário) com sintaxe quebrada, o JSON.parse() falha e lança erro.

1. Node.js: JavaScript Fora do Navegador (Cap. 07)

Antigamente o JavaScript só rodava dentro do navegador. O Node.js é um ambiente de execução (runtime) que pega o motor V8 (o mesmo do Chrome) e deixa o JS rodar direto no computador/servidor!

⚠️
Não confunda Ambiente × Linguagem × Biblioteca!

• JavaScript é a linguagem de programação.
• Node.js é um ambiente de execução para rodar JS fora do navegador (NÃO é outra linguagem nem biblioteca de telas!).
• React é uma biblioteca JS para construir interfaces visuais.

Parte da Aplicação O que faz?
Front-end Interface e interações que o usuário vê e usa no navegador.
Servidor / Back-end Recebe pedidos, aplica regras de negócio e processa dados (ex.: com Node.js).
Banco de dados Guarda e consulta os registros da aplicação de forma estruturada. 
// arquivo: saudacao.js
const sistema = "Agenda online";
console.log(`Aplicacao: ${sistema}`);

// Para rodar direto no terminal (sem abrir HTML nenhum):
// node saudacao.js
  • NPM: gerenciador de pacotes que facilita instalar código reutilizável no projeto.
  • Execução não bloqueante: enquanto aguarda uma tarefa de entrada/saída (como ler arquivo ou rede), o Node.js continua atendendo outras requisições sem travar.
  • Comunicação cliente-servidor (HTTP): o Node.js implementa APIs que respondem aos métodos HTTP: GET, POST, PUT, PATCH e DELETE.

2. Web Components: Peças Reutilizáveis Nativas do Navegador (Cap. 09)

Em vez de copiar e colar o mesmo HTML e CSS em 10 páginas, os Web Components permitem criar suas próprias peças reutilizáveis usando recursos nativos do próprio navegador (sem precisar instalar React!).

1. Custom Elements

Cria e registra novas tags HTML personalizadas (ex.: <mensagem-info>).

2. Shadow DOM

Cria uma "bolha" interna (attachShadow()) que isola a estrutura e os estilos CSS do componente.

3. Template (<template>)

Define um molde de HTML que pode ser clonado e reaproveitado várias vezes.

4. Slots (<slot>)

Espaços reservados onde quem usa o componente encaixa títulos ou textos personalizados.

// A classe herda de HTMLElement (base de todo elemento HTML)
class MensagemInfo extends HTMLElement {
  // connectedCallback() roda automaticamente quando a tag entra na página
  connectedCallback() {
    this.textContent = "Componente carregado";
  }
}

// Registra a nova tag. REGRA: tudo minúsculo e COM HÍFEN!
customElements.define("mensagem-info", MensagemInfo);
💡
Regra do Hífen nos Custom Elements

O nome da tag personalizada precisa ter letras minúsculas e um hífen (ex.: mensagem-info, meu-cartao) para nunca dar conflito com tags padrão do HTML (div, p, button).

3. React: Interfaces por Componentes, props e state (Cap. 10)

O React é uma biblioteca JavaScript para montar telas dividindo tudo em pequenas peças reutilizáveis (componentes) que formam uma árvore (cabeçalho, lista, cartões, botões).

Ele usa JSX: uma sintaxe que parece HTML escrito dentro do código JavaScript (as ferramentas do projeto convertem esse JSX em JS comum para o navegador entender).

Conceito O que significa em português simples?
props Dados que vêm de fora (quem usa o componente passa para ele, como um argumento).
state Dados de dentro do componente que mudam quando o usuário interage.
useState() Hook que cria um estado e devolve dois itens: [valorAtual, funcaoParaAtualizar]. 
// 1. Componente recebendo PROPS (vem de fora)
function Etiqueta(props) {
  return <span>Categoria: {props.tipo}</span>;
}

function App() {
  return <Etiqueta tipo="Livros" />; // passa "Livros" na prop tipo
}
// 2. Componente com STATE (muda ao clicar sem recarregar a página)
import { useState } from "react";

function Alternador() {
  // visivel começa false; setVisivel é a função usada para trocar esse valor
  const [visivel, setVisivel] = useState(false);

  return (
    <button onClick={() => setVisivel(!visivel)}>
      {visivel ? "Ocultar" : "Mostrar"}
    </button>
  );
}
📘
Modo Declarativo + Virtual DOM

No React você trabalha de forma declarativa: você descreve como a tela deve parecer para cada estado, e o React cuida de atualizar só o necessário sem recarregar a página inteira (usando o Virtual DOM para comparar o que mudou).
Em comum com Web Components: a ideia de reutilização de componentes (Web Components é nativo do navegador; React é biblioteca externa).

Como os 11 Conteúdos Trabalham Juntos em Um Site Real (Cap. 11)

Na prova, o mais importante é saber para que serve cada tecnologia e como elas se ligam em uma aplicação real (como uma plataforma de reservas acadêmicas). Nenhuma tecnologia substitui todas as outras — cada uma resolve uma etapa:

Jornada de uma ação do usuário até a resposta da interface e do servidor.
O que acontece na aplicação Qual recurso entra em ação?
Pessoa preenche um formulário ou clica HTML + DOM + input + addEventListener() (+ preventDefault())
Texto digitado é limpo e conferido trim(), métodos de string (toLowerCase(), length) e if
Lista de atividades é filtrada ou transformada Arrays com filter(), map() e push()
Mensagem dinâmica aparece na tela textContent (seguro) ou innerHTML + Template Strings (`...${}...`)
Preferência de aparência fica salva para a próxima visita localStorage com pares chave-valor (e JSON se for objeto/array)
Interface conversa com sistemas externos Comunicação HTTP (GET/POST/...) + dados em texto JSON
Servidor executa regras de negócio em JS Node.js (runtime com motor V8) no back-end
Tela é montada em blocos reaproveitáveis Web Components (nativo) ou React (biblioteca)

⏱️ Roteiro Express de Sobrevivência (Revisão Rápida)

Foque primeiro nos pontos em que mais gente perde questão por detalhe bobo:

🔥 Prioridade Máxima (Cai Direto)

  • JS Básico: const vs let; campos/prompt() chegam como string → usar Number(); === compara valor e tipo.
  • Arrays: índice começa em 0; último índice = length - 1; push() altera o array e retorna novo tamanho; filter() e map() criam novo array.
  • DOM & Eventos: querySelector() pega só o 1º; preventDefault() só cancela a ação padrão (não valida nem envia); textContent (texto puro/seguro) vs innerHTML (interpreta tags).
  • localStorage & JSON: localStorage só guarda string (retorna null se não achar); JSON exige aspas duplas, sem vírgula final, sem comentários/funções; stringify (vira texto) vs parse (vira objeto).

⚡ Prioridade Rápida (Seminários & Conceitos)

  • Strings: Template Strings usam crases e ${...}; length é propriedade (sem ()), trim() e toLowerCase() são métodos (com ()).
  • Node.js: é um runtime (motor V8) para rodar JS fora do navegador (back-end/APIs), com NPM e execução não bloqueante.
  • Web Components: recurso nativo do navegador com 4 peças (Custom Elements com hífen no nome, Shadow DOM, Template e Slots).
  • React: biblioteca de UI com JSX, forma declarativa, Virtual DOM, props (vem de fora) e state/useState() (muda dentro).

1. Comparativo Rápido: Arrays, Strings e DOM

Recurso O que faz Pegadinha para lembrar
push() Adiciona no fim do próprio array Muda o array original e retorna o novo length.
filter() Filtra itens por condição (callback) Devolve um novo array sem mexer no original.
map() Transforma cada item (callback) Devolve um novo array com o mesmo tamanho.

2. Comparativo das Tecnologias (Seminários)

Tecnologia O que é? Palavras-chave da Prova

3. Checklist Anti-Pegadinha da Prova

⚡ JavaScript, DOM & Storage

  • "6" + 2 dá "62" (texto concatena!); use Number("6") para somar.
  • === compara valor e tipo; % pega o resto da divisão.
  • Último índice de array não vazio é length - 1.
  • document.querySelector() retorna só o 1º elemento que bater.
  • localStorage.getItem() devolve null se a chave não existir; não serve para senhas nem substitui banco no servidor.

🧩 JSON, Node, Web Components & React

  • JSON é texto, não objeto em memória; erro no texto quebra o JSON.parse().
  • Node.js não é uma nova linguagem — a linguagem continua sendo JavaScript.
  • Custom Element precisa de letras minúsculas + hífen (tag-aqui).
  • No React: props vem de quem chama; state muda dentro via useState().
  • Web Components e React compartilham a ideia de reutilização de componentes.
