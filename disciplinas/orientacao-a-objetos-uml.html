Orientação a Objetos e UML Sem Mistério (Java)

Guia direto para prova objetiva (Unidade 2 — Aulas 5 a 10 + Aula 20 Herança): explicação simples do zero, código Java traduzido, pegadinhas de compilação, 3 simuladores visuais e 20 questões comentadas.

1. Classe × Objeto × Abstração (A Planta e a Casa!)

Na Programação Orientada a Objetos (POO), a gente para de jogar tudo solto dentro do main e passa a modelar coisas do mundo real (um carro, uma conta bancária, um aluno, um produto).

📐 Classe (O Molde)

É a planta da casa ou a forma de bolo. Ela não é o objeto em si: ela apenas descreve quais dados e ações os objetos daquele tipo terão.

🏠 Objeto / Instância

É a casa construída a partir da planta! A partir de 1 classe Carro, podemos criar vários objetos independentes: meuCarro e carroDoPaulo.

🎯 Abstração

É simplificar focando no que importa para o sistema. Para um app de multas, o Carro precisa de placa, cor, modelo; para um jogo de corrida, de velocidade, acelerar().

A Atributos (Estado): variáveis da classe que guardam dados (modelo, saldo).
M Métodos (Comportamento): ações que o objeto faz (acelerar(), sacar()).
📝
Boas Práticas que Caem em Questão Teórica
  • Classe começa com letra maiúscula (PascalCase): ContaBancaria, Celular.
  • Atributo e método começam com minúscula (camelCase): calcularMedia().
  • Uma classe pública por arquivo .java com o mesmo nome: Carro.java e Principal.java.

2. Criando Objetos com new, Operador Ponto (.) e Stack × Heap

Quando você escreve Carro c1 = new Carro();, duas regiões diferentes da memória trabalham juntas:

c2 = c1 copia apenas o endereço na Stack — ambos apontam para o mesmo objeto no Heap!
Carro c1 = new Carro();    // cria objeto #1 no Heap e guarda o endereço em c1
c1.cor = "prata";          // operador ponto (.) acessa atributo do objeto
c1.acelerar();             // operador ponto (.) chama método do objeto

Carro c2 = c1;             // NÃO cria carro novo! Copia a referência!
c2.cor = "azul";
System.out.println(c1.cor); // Imprime "azul" (é o mesmo carro!)

Carro c3 = null;           // não aponta para nenhum objeto
c3.acelerar();             // ERRO em execução: NullPointerException!
⚠️
Pegadinhas Clássicas de Stack × Heap e Referência
  • Tipos primitivos (int, double) guardam o valor na Stack; objetos ficam sempre no Heap (gerenciados pelo Garbage Collector).
  • c2 = c1 não duplica o objeto — apenas cria outro ponteiro para o mesmo objeto. Para ter dois carros independentes, precisa de dois new Carro()!
  • Esquecer o new ou usar null: Carro c = null; c.cor = "azul"; gera NullPointerException.

3. Valores Padrão de Atributos (Quando Você Usa new)

Ao criar um objeto com new, o Java inicializa automaticamente todos os atributos da classe. Mas atenção: isso não vale para variáveis locais dentro de métodos!

Tipo do Atributo Valor Padrão Exemplo
int, long, short, byte 0 int idade; → 0
double, float 0.0 double saldo; → 0.0 (imprime com .0!)
boolean false boolean ativo; → false
char '\u0000' caractere vazio
String (e qualquer objeto) null String nome; → null
📘
Atributo × Variável Local

Um atributo da classe nasce com valor padrão (0, 0.0, false, null). Já uma variável local (declarada dentro de um método ou main) precisa ser inicializada manualmente antes de ser usada, senão não compila!

1. Métodos void × Métodos com Retorno + Parâmetros

Métodos são as ações do objeto. Em Java, a primeira palavra da assinatura diz se o método devolve alguma resposta ou só executa uma tarefa.

⚙️ void — Só executa

Não devolve nenhum valor. Usado para imprimir ou alterar atributos do próprio objeto.

void depositar(double valor) {
    saldo += valor;
}

↩️ Com Tipo — Devolve valor

O tipo (double, boolean, String) substitui void e usa return.

boolean sacar(double valor) {
    if (valor <= saldo) {
        saldo -= valor;
        return true;
    }
    return false;
}
💡
Detalhes Importantes dos Slides (Aulas 6 e 7)
  • return encerra o método imediatamente e devolve o resultado para quem chamou (pode guardar em variável ou imprimir direto).
  • Método chama método: dentro da mesma classe, situacao() pode chamar calcularMedia() diretamente.
  • Objeto como parâmetro: um método pode receber outro objeto! Ex: atacar(Jogador alvo) chama alvo.receberDano(this.ataque).

2. Sobrecarga de Métodos (Overloading)

Sobrecarga é criar dois ou mais métodos com o mesmo nome na mesma classe, mas com lista de parâmetros diferente (quantidade diferente ou tipos diferentes). O Java escolhe qual chamar olhando os argumentos! 

class Calculadora {
    int somar(int a, int b) { return a + b; }          // 2 inteiros
    double somar(double a, double b) { return a + b; } // tipos diferentes -> OK!
    int somar(int a, int b, int c) { return a + b + c; } // quantidade diferente -> OK!
}

class ContaBancaria {
    void depositar(double valor) { ... }
    void depositar(double valor, String descricao) { ... } // sobrecarga válida!
}
⚠️
Pegadinha Clássica de Prova: Só Mudar o Retorno NÃO Compila!

Se você tiver int somar(int a, int b) e double somar(int a, int b) na mesma classe, dá ERRO DE COMPILAÇÃO! Mudar apenas o tipo de retorno (mantendo nome e parâmetros idênticos) NÃO é sobrecarga válida.

3. A Palavra-chave this (Os 3 Usos)

this significa "este objeto aqui" (é a referência para o próprio objeto que está executando o método).

❌ Sem this — Armadilha!

void setNome(String nome) {
    nome = nome; // atribui o parâmetro a ele mesmo!
} // o atributo da classe NÃO muda!

✅ Com this — Correto!

void setNome(String nome) {
    this.nome = nome; // atributo = parâmetro
}
  • 1. Resolver ambiguidade: quando o parâmetro tem o mesmo nome do atributo (this.nome = nome).
  • 2. Encadear construtores: this(...) dentro de um construtor chama outro construtor da mesma classe.
  • 3. Passar o próprio objeto: metodo(this) envia a referência do objeto atual para outro método.

1. O que é um Construtor? (E as 2 Regras de Sintaxe!)

Sem construtor, você precisa criar o objeto vazio e preencher atributo por atributo em várias linhas (e corre o risco de esquecer algum). O construtor é um bloco especial chamado automaticamente no momento do new para o objeto já nascer inicializado!

1 Mesmo nome da classe: classe Carro → construtor Carro(...).
2 NÃO tem retorno — nem void! Se colocar void, vira método comum! 
public class Carro {
    String modelo;
    String cor;
    int velocidade;

    // Construtor parametrizado: mesmo nome da classe, SEM void!
    Carro(String modelo, String cor) {
        this.modelo = modelo;
        this.cor = cor;
        this.velocidade = 0;
    }
}
// No main:
Carro c = new Carro("Fusca", "azul"); // já nasce pronto!

2. Construtor Padrão (Default) × Construtor Parametrizado

Esta é uma das questões mais clássicas de prova objetiva em Java. Entenda o comportamento automático do compilador:

🤖 Quando você NÃO escreve nenhum

Se a classe não tiver nenhum construtor escrito, o Java cria um construtor padrão implícito sem parâmetros (public Carro() {}). Os atributos ficam com valores padrão (null, 0, false).

💥 Quando você escreve UM parametrizado

O construtor padrão implícito DESAPARECE! Se você criou Carro(String m) e não escreveu Carro() {}, chamar new Carro() vazio dá ERRO DE COMPILAÇÃO!

3. Sobrecarga de Construtores e Encadeamento this(...)

Assim como métodos, uma classe pode ter vários construtores com parâmetros diferentes (sobrecarga de construtores). Para não repetir código entre eles, um construtor pode chamar outro da mesma classe usando this(...). 

public class Produto {
    String nome;
    double preco;
    int estoque;

    Produto() {
        this("Sem nome", 0.0, 0); // chama o construtor de 3 parâmetros!
    }

    Produto(String nome, double preco) {
        this(nome, preco, 0); // DEVE ser a 1a linha do construtor!
    }

    Produto(String nome, double preco, int estoque) {
        this.nome = nome;
        this.preco = preco;
        this.estoque = estoque;
    }
}
⚠️
Regra de Ouro do this(...)

A chamada this(...) precisa ser obrigatoriamente a primeira linha dentro do construtor. Se houver qualquer outra linha antes dela, o código não compila.

1. Membros de Instância × Membros static (Da Classe)

Atributos normais (de instância) existem uma vez para cada objeto criado. Já um membro static pertence à CLASSE inteira: existe uma única cópia na memória compartilhada por todos os objetos!

Critério Membro de Instância (sem static) Membro static (da Classe)
Pertence a Cada objeto individual À classe inteira
Como acessar objeto.atributo / objeto.metodo() Classe.atributo / Classe.metodo()
Memória Uma cópia por objeto criado Uma única cópia compartilhada
Pode usar this? Sim Não
Exemplos dos slides nome, saldo, cor totalCarros, Math.PI, Math.sqrt(4) 
public class Carro {
    String modelo;                 // de instância (cada carro tem o seu)
    static int totalCarros = 0;    // da classe (um contador único para todos)

    Carro(String modelo) {
        this.modelo = modelo;
        totalCarros++;             // incrementa a cada new Carro()
    }

    static void exibirTotal() {
        System.out.println("Total: " + totalCarros);
        // System.out.println(modelo);     // ERRO! static não acessa atributo de instância!
        // System.out.println(this.modelo); // ERRO! static não tem this!
    }
}
⚠️
Pegadinha Nº 1 de static

Um método static NÃO pode acessar atributos de instância nem usar this! Motivo lógico: você chama Carro.exibirTotal() sem precisar de nenhum objeto — então o método não tem como saber de qual carro seria o this.modelo!

2. Constantes com final (static final × final de Instância)

A palavra-chave final transforma um atributo em imutável depois de atribuído: tentar alterar seu valor depois gera erro de compilação.

🔒 static final (Constante de Classe)

Valor fixo, único para a classe inteira e que nunca muda. Convenção: NOME_EM_MAIUSCULAS.
Ex: static final double TAXA_JUROS = 0.015;, Math.PI, MAX_LIVROS = 100.

🪪 final sem static (Constante de Instância)

Cada objeto tem o seu valor próprio (ex: CPF, matrícula, ISBN, número da conta), definido uma única vez no construtor e nunca mais alterado!
Ex: c1.numero = 99; // ERRO!

Como tudo se junta no Sistema de Biblioteca (Aula 10)

public class Livro {
    String titulo, autor;
    final String isbn;       // constante de instância: cada livro tem o seu, nunca muda
    boolean emprestado;

    Livro(String titulo, String autor, String isbn) {
        this.titulo = titulo;
        this.autor = autor;
        this.isbn = isbn;    // atribuído uma única vez aqui no construtor!
        this.emprestado = false;
    }

    void exibir() {
        System.out.println(titulo + " - " + (emprestado ? "EMPRESTADO" : "DISPONÍVEL"));
    }
}

1. Por que Herança? E a Regra de Ouro: "É UM" × "TEM UM"

Imagine escrever nome, cpf e apresentar() repetidos em Aluno, Professor e Funcionario. A herança coloca o que é comum em uma superclasse (classe geral, ex: Pessoa) e deixa apenas o que é específico nas subclasses (classes filhas).

✅ Regra do "É UM" → Use Herança (extends)

  • Carro É UM Veículo
  • Aluno É UMA Pessoa
  • Cachorro É UM Animal
  • ContaCorrente É UMA Conta

❌ Relação "TEM UM" → Use Composição!

  • Motor É UM Carro ✗ (Carro TEM UM Motor)
  • Endereço É UMA Pessoa ✗ (Pessoa TEM UM Endereço)
  • Livro É UMA Biblioteca ✗ (Biblioteca TEM Livros)
  • Teclado É UM Computador ✗
⚠️
Pegadinha Conceitual da Aula 20

Reaproveitar código sozinho NÃO justifica herança! Só use extends quando a subclasse for realmente uma versão especializada da superclasse ("É UM"). Além disso, Java NÃO permite herança múltipla de classes: class Smartphone extends Camera, Telefone é inválido (erro de compilação)!

2. Notação UML de Herança (Como Aparece nos Slides)

Nos diagramas UML das aulas, cada classe é um retângulo dividido em 3 partes e a herança é desenhada com uma seta que aponta do filho para o pai:

Não erre na prova: a seta/triângulo de herança UML aponta sempre para a classe MAIS GERAL (superclasse).
  • Herança em vários níveis: Pessoa → Funcionario → Professor (Professor É UM Funcionario e também É UMA Pessoa).
  • Herança hierárquica: várias subclasses compartilham a mesma superclasse (Cachorro, Gato e Passaro estendem Animal).

3. extends, private × protected e Construtores com super(...)

Com class Aluno extends Pessoa, o objeto Aluno contém a parte Pessoa + a parte específica de Aluno. Mas existem 3 regras fundamentais que sempre caem em prova:

🔐
Regra 1: Acesso a Atributos private vs protected

Uma subclasse NÃO acessa diretamente atributos private da superclasse (preserva o encapsulamento — tentar nome = "Ana" direto em Aluno dá erro!).
Duas soluções: (1) usar métodos públicos getNome() / setNome() da superclasse, ou (2) declarar o atributo como protected (visível para a própria classe e suas subclasses).

⚠️
Regra 2: Construtores NÃO São Herdados — Ordem e super(...)!
  • Ordem de execução: ao rodar new B() (onde B extends A), o Java inicializa primeiro a superclasse (A) e depois a subclasse (B)!
  • super() automático: se você não escrever, o Java tenta inserir super() vazio na 1ª linha do construtor do filho.
  • Erro clássico: se Pessoa só tem Pessoa(String nome) (sem construtor vazio), um construtor Aluno() {} NÃO COMPILA! Você precisa escrever super(nome); na primeira instrução do construtor do filho.
  • this(...) × super(...): nunca podem ser usados juntos no mesmo construtor como primeira chamada!
class Pessoa {
    private String nome;
    Pessoa(String nome) { this.nome = nome; }
    void apresentar() { System.out.println("Nome: " + nome); }
}

class Aluno extends Pessoa {
    private int matricula;
    Aluno(String nome, int matricula) {
        super(nome);               // 1a linha! Inicializa a parte Pessoa
        this.matricula = matricula; // depois inicializa a parte Aluno
    }

    @Override
    void apresentar() {
        super.apresentar();        // chama a versão da superclasse ("Nome: ...")
        System.out.println("Matrícula: " + matricula);
    }
}

4. Sobrescrita (@Override) × Sobrecarga (Overload)

Os nomes são parecidos e as provas adoram misturar os dois! Decorando esta tabela você não cai mais nessa pegadinha:

Característica Sobrescrita (@Override) Sobrecarga (Overload)
Exige herança? Sim (superclasse → subclasse) Não (ocorre na mesma classe)
Assinatura (nome + parâmetros) Mesma assinatura da superclasse Mesmo nome, parâmetros diferentes
Objetivo Trocar / especializar comportamento herdado Oferecer formas diferentes de chamar um método
Papel de @Override Faz o compilador avisar se o método não existir no pai (evita erro de digitação) Não se aplica

🔥 Top Pegadinhas de Código (Certeza de Cair!)

  • Construtores: NÃO têm retorno (nem void); ao criar um parametrizado, o padrão vazio desaparece.
  • Herança + Construtor: ordem é Pai → Filho; se o pai não tem construtor vazio, o filho precisa chamar super(param) na 1ª linha.

⚡ Conceitos & UML (Pontos Garantidos!)

  • Classe × Objeto: classe é o molde/planta; objeto é a instância no Heap.
  • Atributos vs Locais: atributos recebem padrão (0, 0.0, false, null); variáveis locais não!
  • "É UM" × "TEM UM": Herança só vale para "É UM" (Aluno É UMA Pessoa). Carro/Motor é composição ("TEM UM").
  • UML dos slides: seta com triângulo aponta para a superclasse; - = private, + = public.
  • Herança múltipla: Java não permite class A extends B, C.

1. Palavras-Chave Essenciais

Palavra / Símbolo Para que serve Pegadinha para não errar
new Cria o objeto no Heap e devolve referência Sem new (ou com null), acessar membro dá NullPointerException
this Referência ao objeto atual Sem this.nome = nome, parâmetro atribui a si mesmo
this(...) Chama outro construtor da mesma classe Deve ser a 1ª linha; não pode conviver com super(...) no mesmo construtor
static Membro pertence à classe (1 cópia única) Não acessa atributo de instância nem usa this
final Impede alterar o valor após inicialização static final = constante da classe; final = constante da instância (no construtor)
extends Declara herança (Sub extends Super) Java só aceita 1 superclasse por vez (sem herança múltipla de classes)
super(...) Chama o construtor da superclasse Deve ser a 1ª linha; obrigatório se o pai não tiver construtor vazio
super.metodo() Chama versão da superclasse dentro de método Útil quando você sobrescreveu o método mas quer aproveitar a parte geral do pai
@Override Indica sobrescrita de método herdado Faz o compilador checar se a assinatura bate com a do pai
protected / - / + Visibilidade (- private, + public) Subclasse não acessa private direto; usa getters públicos ou protected

2. Checklist Final Antes de Marcar a Alternativa

🔍 Ao ler código Java na questão

  • Tem construtor com parâmetro e chamaram new Classe() vazio? → Erro de compilação!
  • Tem construtor com void na frente? → Não é construtor, é método comum!
  • super(...) ou this(...) está depois de outra linha? → Erro de compilação!
  • Subclasse acessando atributo private do pai direto? → Erro de compilação!

📐 Ao ler questão de UML e Conceitos

  • Para onde aponta o triângulo da seta UML? → Sempre para a superclasse (mais geral).
  • c2 = c1 criou novo objeto? → Não, apenas copiou o endereço na Stack.
  • double sem inicialização em atributo imprime o quê? → 0.0 (com decimal!).
  • Motor herda de Carro? → Falso! Motor NÃO É UM Carro (é composição: "tem um").
