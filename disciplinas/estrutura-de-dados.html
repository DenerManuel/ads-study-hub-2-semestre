Estrutura de Dados Sem Mistério: Grafos, Listas, Árvores ABB e AVL

Guia direto para quem tem menos de 1 semana para a prova: explicação do zero (mesmo se você não entendeu nada na aula), código em C traduzido para o português, pegadinhas clássicas, 3 simuladores visuais e 20 questões de fixação comentadas.

1. O que é um Grafo? (Pense em Cidades e Redes Sociais)

Esqueça a matemática pesada por 1 minuto. Um Grafo é só um desenho formado por bolinhas (as coisas) ligadas por linhas ou setas (as conexões). Mapa do metrô, amigos no WhatsApp, seguidores no Instagram e rotas de GPS são grafos!

V Vértices (Nós): as bolinhas (pessoas, cidades, servidores).
A Arestas: os tracinhos ou setas que ligam dois vértices.
Exemplo clássico dos slides (Aula 6, slide 5): vértices, arestas e laço.
⚠️
Pegadinha nº 1 da Prova: O Laço conta +2!

Um laço é uma linha que sai de uma bolinha e volta para ela mesma. Pense em uma corda com as duas pontas amarradas no mesmo poste: quantas pontas encostam no poste? Duas! Por isso, em grafos sem seta (não direcionados), cada laço soma +2 no grau daquele vértice. No desenho acima, o nó 2 tem 3 linhas normais + 1 laço = 3 + 2 = 5!

2. Os 3 Tipos que Caem na Prova + Como Contar Setas

🤝 Não Direcionado

Mão dupla (sem seta). Se 1 liga com 2, então 2 também liga com 1.
Pense: amizade no Facebook.

➡️ Direcionado (Dígrafo)

Mão única (com seta). A seta A → B só vale na ida, não garante volta.
Pense: seguir no Instagram.

⚖️ Ponderado (Com Peso)

Cada linha tem um número (km, tempo, custo).
Pense: GPS escolhendo o caminho com menor soma de km, não com menos curvas!

Macete para Dígrafo (Com Setas): Entrada × Saída

Não confunda na hora da prova! Olhe sempre para a bolinha e conte:

  • Grau de Entrada: quantas pontas de seta chegam nela (apontam para dentro).
  • Grau de Saída: quantos rabos de seta saem dela (apontam para fora).
D só recebe setas (entrada = 2, saída = 0). A só envia (entrada = 0, saída = 1).

🛤️ Caminho vs 🔁 Ciclo

Caminho: sequência de passos de um ponto a outro (A → B → D).
Ciclo: caminho fechado que volta para onde começou (A → B → C → A).

🌐 Grafo Conexo

Sem "ilhas isoladas": saindo de qualquer bolinha, você consegue chegar em qualquer outra bolinha seguindo as linhas.

3. Como o Computador Guarda um Grafo? (Matriz × Lista)

Na prova, a professora pode te dar uma tabela de 0 e 1 (Matriz) ou uma Lista e pedir para você interpretar. Veja como ler em 5 segundos:

📊 Matriz de Adjacência (Tabela N × N)

• Leia assim: "Linha i vai para Coluna j?"
• Se vale 1 = tem ligação. Se vale 0 = não tem.
• Regra do Espelho: se o grafo não tem seta, a matriz é simétrica (M[1][2] == M[2][1]).
• Onde fica o laço? Na diagonal principal (M[4][4] = 1)!
• Desvantagem: se há poucas arestas (grafo esparso), gasta memória à toa guardando um monte de zeros.

📋 Lista de Adjacência (Agenda de Contatos)

• Cada vértice tem uma listinha só com seus vizinhos reais.
• Exemplo: 1 → 2 → 4 significa "do 1 dá para ir para o 2 e para o 4".
• Vantagem gigante: economiza muita memória em grafos com poucas conexões (não guarda zeros!).
• No dígrafo: a seta 1 → 2 só entra na lista do 1. Na mão dupla, entra na do 1 e na do 2.

1. O que é Lista Simples? (Esqueça os termos difíceis!)

Um vetor (array) é como uma fileira de cadeiras coladas no cinema: você acha a cadeira 50 na hora, mas se alguém quiser entrar no meio da fila, todo mundo precisa levantar e andar uma cadeira para o lado!

Já a Lista Simplesmente Encadeada (LSL) funciona como um trem de vagões (ou uma caça ao tesouro): cada vagão (chamado de Nó) fica em qualquer lugar da memória e carrega apenas duas coisas: o dado (ex: número 10) e o endereço do próximo vagão (prox).

📌
Tradutor de C para Humanos (Leia antes de ver qualquer código!)

Se você travava ao ver *, ** e ->, decore só estas 4 traduções:
1. No* p → "p é um GPS que guarda o endereço de um vagão (não é o vagão!)."
2. p->dado → "Vá até o vagão onde p aponta e leia o número dentro dele."
3. p = p->prox → "Dê 1 passo para frente no trem (p agora aponta para o próximo vagão)."
4. No** headRef → "Permissão para trocar quem é o 1º vagão lá no main()". Se a função só lê ou imprime (ex: busca), usa só No*. Se pode mudar o começo da lista (inserir/remover no início ou destruir), precisa de No** (e dentro da função, *headRef significa "a placa head original")! 

typedef struct No {
    int dado;          // O valor guardado no vagão (ex: 10)
    struct No* prox;   // O endereço do próximo vagão (ou NULL se for o último)
} No;

No* criaNo(int valor) {
    No* novo = malloc(sizeof(No)); // Pede memória na RAM para 1 vagão novo
    if (novo == NULL) { perror("malloc falhou"); exit(EXIT_FAILURE); }
    novo->dado = valor;            // Coloca o valor dentro do vagão
    novo->prox = NULL;             // Nasce desconectado (aponta para nada)
    return novo;
}

2. As 3 Inserções na LSL (Código C Traduzido)

A) Inserir no Início — O(1) (Instantâneo!)

void insereInicio(No** headRef, int valor) {
    No* novo = criaNo(valor);
    novo->prox = *headRef; // PASSO 1: novo vagão segura o antigo 1º vagão!
    *headRef = novo;       // PASSO 2: placa "head" passa a apontar para o novo!
}
⚠️
Pegadinha Clássica de Prova: Inverter essas 2 linhas!

Se o programador fizer *headRef = novo; ANTES de novo->prox = *headRef;:
1. O endereço do antigo 1º vagão é apagado para sempre (todo o resto do trem se perde na memória → vazamento de memória!).
2. Na linha seguinte, novo->prox recebe *headRef, que agora é o próprio novo! Ou seja, o vagão fica apontando para ele mesmo (loop infinito!).
Regra: "Primeiro segura o trem na mão do novo; só depois muda a placa head!"

B) Inserir no Fim — O(n)

void insereFim(No** headRef, int valor) {
    No* novo = criaNo(valor);
    if (*headRef == NULL) {     // Se o trem está vazio, o novo já é o 1º vagão!
        *headRef = novo;
        return;
    }
    No* aux = *headRef;         // Cria um inspetor "aux" começando no 1º vagão
    while (aux->prox != NULL) { // Enquanto existir um vagão depois de aux...
        aux = aux->prox;        // ...dá 1 passo para frente!
    }                           // Quando o while acaba, aux está exatamente no ÚLTIMO vagão!
    aux->prox = novo;           // Engata o novo vagão atrás do último!
}

C) Inserção Ordenada (mantém crescente) — O(n)

void insereOrdenado(No** headRef, int valor) {
    No* novo = criaNo(valor);
    // Se lista vazia OU valor é menor que o 1º, entra logo no começo!
    if (*headRef == NULL || valor < (*headRef)->dado) {
        novo->prox = *headRef;
        *headRef = novo;
        return;
    }
    No* aux = *headRef;
    // Tradução: "enquanto houver próximo E o dado do próximo ainda for menor que valor..."
    while (aux->prox != NULL && aux->prox->dado < valor) {
        aux = aux->prox; // ...ande! Para UM PASSO ANTES de onde deve encaixar.
    }
    novo->prox = aux->prox; // 1º: novo segura quem estava na frente
    aux->prox = novo;       // 2º: aux aponta para o novo
}
🧠
Por que o while checa aux->prox->dado < valor (e não aux->dado)?

Porque na LSL não dá para dar ré! Se aux já pisasse no nó maior que valor, você não teria como voltar para mudar o ponteiro do nó anterior. Olhando para o próximo (aux->prox->dado), aux para exatamente atrás da vaga onde o novo nó entra!

3. Remoções e Destruição (Onde Mais Tem Pegadinha de Código!)

// 1. Remover do Início — O(1)
void removeInicio(No** headRef) {
    if (*headRef == NULL) return;   // Lista vazia? Não faz nada.
    No* temp = *headRef;            // Anota o endereço do 1º para poder dar free() depois
    *headRef = (*headRef)->prox;    // Placa head pula direto para o 2º vagão
    free(temp);                     // Libera o antigo 1º vagão da memória
}

// 2. Remover do Fim — O(n)
void removeFim(No** headRef) {
    if (*headRef == NULL) return;
    if ((*headRef)->prox == NULL) { // Caso especial: só tem 1 vagão!
        free(*headRef);
        *headRef = NULL;            // Lista ficou vazia
        return;
    }
    No* aux = *headRef;
    // Tradução: "enquanto o vagão DA FRENTE ainda não for o último..."
    while (aux->prox->prox != NULL) {
        aux = aux->prox;            // PARA NO PENÚLTIMO VAGÃO!
    }
    free(aux->prox);                // Apaga o último vagão
    aux->prox = NULL;               // O penúltimo agora fecha o trem com NULL!
}

// 3. Remover por Valor — O(n)
void removeValor(No** headRef, int valor) {
    if (*headRef == NULL) return;
    if ((*headRef)->dado == valor) { removeInicio(headRef); return; }
    No* aux = *headRef;
    while (aux->prox != NULL && aux->prox->dado != valor) {
        aux = aux->prox;            // Para um passo ANTES do vagão que queremos apagar
    }
    if (aux->prox == NULL) return;  // Chegou ao fim e não achou o valor
    No* temp = aux->prox;           // temp é o vagão que vai morrer
    aux->prox = temp->prox;         // O anterior "pula" temp e aponta para o próximo dele
    free(temp);
}

Destruir a Lista Sem Cair no Erro "Use-After-Free"

❌ JEITO ERRADO (Cai na Prova!)

while (atual != NULL) {
    free(atual);
    atual = atual->prox; // ERRO!
}

Você demoliu a casa (free) e depois tentou entrar nela para ler onde fica a próxima (atual->prox). Isso é use-after-free!

✅ JEITO CERTO

while (atual != NULL) {
    No* proximo = atual->prox; // Salva ANTES!
    free(atual);
    atual = proximo;
}
*headRef = NULL;

Anota o endereço do próximo vagão num papel (proximo), só então apaga o atual, e no fim zera *headRef.

1. Lista Dupla (LDE): Agora o Trem Tem Ré e Painel de Controle!

Na Lista Simples, você só andava para frente — por isso remover no fim dava trabalho (O(n)). Na Lista Duplamente Encadeada (LDE), fazemos duas melhorias gigantes:

  • Cada vagão ganha dois ponteiros: ant (olha para trás) e prox (olha para frente).
  • Criamos uma caixinha de controle chamada Lista que guarda direto o primeiro (ini), o último (fim) e o total de nós (n).

🧱 Vagão Duplo (No)

typedef struct No {
    int dado;
    struct No* ant;  // aponta para trás
    struct No* prox; // aponta para frente
} No;

1º nó tem ant == NULL. Último nó tem prox == NULL.

🎛️ Painel de Controle (Lista)

typedef struct {
    No* ini; // endereço do 1º nó
    No* fim; // endereço do último nó
    int n;   // quantidade de nós
} Lista;

Como fim está sempre à mão, inserir ou remover no final vira O(1)!

🎵
Onde isso existe na vida real? (Questão clássica!)

• Ctrl+Z / Ctrl+Y (Desfazer e Refazer) · Voltar / Avançar no navegador · Playlist (faixa anterior / próxima) · LRU Cache.

2. Inserções e Remoções na LDE (Foco nos Casos Especiais!)

void insereInicio(Lista* L, int valor) {
    No* novo = malloc(sizeof(No));
    novo->dado = valor;
    novo->ant = NULL;         // Vai ser o 1º, então não há ninguém antes dele
    novo->prox = L->ini;      // Aponta para o antigo 1º
    if (L->ini != NULL)       // Se a lista JÁ tinha alguém...
        L->ini->ant = novo;   // ...o antigo 1º aponta de volta para o novo!
    else                      // Se a lista ESTAVA VAZIA...
        L->fim = novo;        // ...o novo também é o último (ini e fim são ele)!
    L->ini = novo;
    L->n++;
}

void insereFim(Lista* L, int valor) {
    No* novo = malloc(sizeof(No));
    novo->dado = valor;
    novo->prox = NULL;        // Vai ser o último, então não há ninguém depois dele
    novo->ant = L->fim;       // Aponta para trás (antigo último)
    if (L->fim != NULL)       // Se a lista JÁ tinha alguém...
        L->fim->prox = novo;  // ...o antigo último aponta para frente (novo)!
    else                      // Se a lista ESTAVA VAZIA...
        L->ini = novo;        // ...o novo também é o primeiro (ini e fim são ele)!
    L->fim = novo;
    L->n++;
}
⚠️
Os 3 Bugs de LDE que Mais Caem na Prova!
  1. Lista vazia recebendo o 1º nó: tanto L->ini quanto L->fim precisam apontar para novo! Se esquecer o else, o outro ponteiro continua NULL.
  2. Lista com 1 único nó sendo removida: quando removemos o último sobrevivente (L->ini == L->fim), a lista fica vazia → AMBOS L->ini e L->fim devem virar NULL! Se só atualizar um deles, o outro fica apontando para memória já liberada com free()!
  3. Esquecer de religar a volta (ant): ida funciona, volta quebra. E nunca esqueça L->n++ / L->n--.

Remoção no Meio Tendo o Ponteiro p — O(1)!

Imagine que você já tem o ponteiro p apontando exatamente para o vagão que quer tirar do meio da LDE. Como p conhece o vizinho de trás (p->ant) e o da frente (p->prox), você só faz os dois vizinhos se darem as mãos: 

// Para remover p (estando no meio, entre dois nós):
p->ant->prox = p->prox; // O vizinho de trás pula p e aponta para o da frente
p->prox->ant = p->ant;  // O vizinho da frente pula p e aponta para o de trás
free(p);
L->n--;

Resumo honesto para prova: LDE é mais rápida nos extremos (O(1) no início e no fim) e remove nó conhecido do meio em O(1), mas a busca por valor continua O(n) e ela gasta mais memória (2 ponteiros por nó em vez de 1).

1. Árvore em 1 Minuto (De Cabeça para Baixo!)

Listas são uma fila reta. Árvores servem para representar hierarquia (pastas do computador, chefes e funcionários). Na computação, desenhamos a árvore de ponta-cabeça: a Raiz fica lá em cima e as Folhas ficam embaixo!

📖 Dicionário Rápido

  • Raiz: nó do topo (único sem pai). Fica no Nível 0.
  • Folha: nó lá embaixo que não tem nenhum filho (grau 0).
  • Grau do nó: quantos filhos ele tem (em árvore binária, no máximo 2: esq e dir).
  • Acíclica e Conexa: não pode formar círculo fechado e todo nó (exceto a raiz) tem exatamente 1 pai.

⚠️ Pegadinha de Definição (Slide 17)

  • Estritamente Binária: todo nó tem 0 ou 2 filhos (é proibido ter apenas 1 filho!).
  • Binária Completa: todas as folhas estão exatamente no mesmo nível (último andar todo preenchido).
  • Quase Completa: diferença de altura entre subárvores é no máximo 1.

2. Os 3 Percursos Clássicos (Certo na Prova!)

Como imprimir todos os nós da árvore? Basta olhar onde está a letra R (Raiz) na sigla:

Pré-ordem: R - E - D

Imprime a Raiz primeiro, depois vai tudo à esquerda, depois à direita.
Uso: mostrar estrutura / clonar árvore.

In-ordem: E - R - D

Vai tudo à esquerda, imprime a Raiz no meio, depois à direita.
Mágica na ABB: sai sempre em ordem crescente!

Pós-ordem: E - D - R

Esquerda, Direita, e a Raiz por último.
Uso de prova: ideal para dar free() (apaga os filhos antes de apagar o pai!).

Macete do contorno: passe por fora da árvore da esquerda para a direita. Pré = borda esquerda; In = por baixo; Pós = borda direita.

3. ABB (Árvore Binária de Busca) + Remoção com Predecessor

🧭
A Regra Única da ABB

Para qualquer nó X: tudo à esquerda é MENOR que X, e tudo à direita é MAIOR que X. (Nesta disciplina, valores repetidos são ignorados).

⚠️
Pegadinha da ABB Degenerada!

Em uma ABB equilibrada, buscar custa O(log n). Mas se você inserir números já em ordem crescente (ex: 10, 20, 30, 40, 50), todo número novo é maior e cai sempre na direita! A árvore vira uma linha reta torta (árvore degenerada) igual a uma Lista Ligada, e a busca despenca para O(n)!

Remoção na ABB — Os 3 Casos (Foco no Caso de 2 Filhos!)

Imagine a árvore com raiz 50, filho esquerdo 30 (que tem filhos 20 e 40) e filho direito 70. Como remover o 50 sem quebrar a regra da ABB? Veja os 3 casos no código oficial dos slides:

  1. 0 filhos (folha, ex: 20): só apaga e devolve NULL.
  2. 1 filho: o pai "pula" o nó removido e adota o único filho dele.
  3. 2 filhos (ex: remover 50): escolhemos o Predecessor — o MAIOR número do lado esquerdo (dá 1 passo para a esquerda e vai tudo para a direita → no exemplo, é o 40!). Copiamos o 40 para o lugar do 50 e depois mandamos remover o nó original do 40 lá embaixo!
No* removeRec(No* r, int k) {
    if (r == NULL) return NULL;                       // Não achou
    if (k < r->chave)      r->esq = removeRec(r->esq, k); // Procura na esquerda
    else if (k > r->chave) r->dir = removeRec(r->dir, k); // Procura na direita
    else {                                            // ACHOU o nó r!
        if (r->esq == NULL) {                         // Tem 0 filhos ou só filho à direita
            No* aux = r->dir; free(r); return aux;
        }
        if (r->dir == NULL) {                         // Só tem filho à esquerda
            No* aux = r->esq; free(r); return aux;
        }
        // CASO DOS 2 FILHOS -> Usa PREDECESSOR (maior valor da subárvore esquerda):
        No* p = maximo(r->esq);                       // 1 passo p/ esq, depois tudo p/ dir
        r->chave = p->chave;                          // Copia a chave do predecessor para r
        r->esq = removeRec(r->esq, p->chave);         // Apaga o nó original de p lá embaixo!
    }
    return r;
}

1. Árvore AVL Sem Sofrimento: A Única Fórmula que Você Precisa

Como vimos na Aula 9, uma ABB comum pode entortar e ficar lenta (O(n)). A Árvore AVL é uma ABB que não deixa nenhum lado ficar alto demais: quando entorta, ela gira os nós (rotações) para manter a busca sempre rápida em O(log n).

📐
Cola Oficial dos Slides para Calcular FB na Prova (Aula 10)

• Lugar vazio (NULL): altura = -1
• Folha (sem filhos): altura = 0
• Qualquer outro nó: altura = 1 + maior altura entre os filhos
• Fator de Balanceamento (FB): FB = altura(Esquerda) - altura(Direita)
• Regra do Jogo: só é aceito FB igual a -1, 0 ou +1. Se bater +2 ou -2, quebrou e precisa rotacionar!

⚖️
Macete Instantâneo de Sinal (Não Erre Nunca Mais!)

• FB Positivo (+1, +2) = lado ESQUERDO mais pesado.
• FB Negativo (-1, -2) = lado DIREITO mais pesado.
• FB = 0 = os dois lados têm a mesma altura.
Exemplo rápido: um nó com 1 folha na esquerda (alt 0) e nada na direita (alt -1) tem FB = 0 - (-1) = +1!

2. Como Saber Qual Rotação Fazer Sem Decorar Tabela!

Quando um nó dá +2 ou -2, olhe para o sinal dele e para o sinal do filho do lado pesado:

📏 Sinais IGUAIS = Linha Reta → Rotação SIMPLES

• LL (+2 e filho esq +1 ou 0): caiu tudo para a esquerda → gira o pai para a DIREITA (lado oposto!).
• RR (-2 e filho dir -1 ou 0): caiu tudo para a direita → gira o pai para a ESQUERDA (lado oposto!).

🦵 Sinais OPOSTOS = "Joelho Dobrado" → Rotação DUPLA

• LR (+2 no pai e -1 no filho esq): faz zigue-zague (ex: 30 → 10 → 20).
1º estica o joelho girando o filho p/ esquerda; 2º gira o pai p/ direita!
• RL (-2 no pai e +1 no filho dir): faz zigue-zague (ex: 10 → 30 → 20).
1º estica o joelho girando o filho p/ direita; 2º gira o pai p/ esquerda!

3. Pegadinhas da AVL na Inserção e Remoção

⚠️
Pegadinha nº 1: Vários nós com |FB| = 2 ao mesmo tempo!

Quando você insere uma folha e volta recalculando os FBs de baixo para cima, às vezes o avô e o bisavô também ficam com -2 (ex: slide 17: nós 7, 6 e 4). Onde rotacionar? Apenas no PRIMEIRO nó desbalanceado que encontrar subindo (o 7)! Quando você conserta esse primeiro lá embaixo, todos os de cima já se arrumam sozinhos!

  • Custo da rotação na inserção: O(1) (máximo 1 rotação simples ou dupla) e a ordem crescente (In-ordem) nunca muda!
  • Como funciona a Remoção na AVL? Remove exatamente como na ABB (folha, 1 filho, 2 filhos com predecessor) e, na volta da recursão (de baixo para cima), recalcula alturas e rotaciona qualquer nó que ficar com |FB| ≥ 2.

Como isso aparece em Código C na Prova?

int altura(No* r) {
    return (r == NULL) ? -1 : r->h; // Vazia vale -1!
}

int fb(No* r) {
    return (r == NULL) ? 0 : altura(r->esq) - altura(r->dir);
}

// Rotação Simples à Direita (caso LL): o filho esquerdo x sobe!
No* rotacaoDireita(No* y) {
    No* x = y->esq;   // x é quem vai virar a nova raiz
    No* T2 = x->dir;  // Salva o filho direito de x para não perder!
    x->dir = y;       // y desce para a direita de x
    y->esq = T2;      // T2 vira filho esquerdo de y
    // Atualiza alturas de baixo para cima (1º y que desceu, depois x que subiu)
    y->h = 1 + max(altura(y->esq), altura(y->dir));
    x->h = 1 + max(altura(x->esq), altura(x->dir));
    return x;         // Devolve x como nova raiz da subárvore
}

⏱️ Roteiro Express de Sobrevivência (Menos de 1 Semana para a Prova)

Sem tempo para ver tudo com calma? Siga exatamente esta ordem de prioridade para garantir os pontos que mais valem na prova:

🔥 Prioridade Máxima (Obrigatório Dominar)

  • Lista Simples (LSL): entender No** vs No*, a ordem das 2 linhas do insereInicio, o while (aux->prox->prox != NULL) do removeFim e o erro use-after-free ao destruir.
  • Árvores & ABB: saber fazer Pré (RED), In (ERD = crescente!) e Pós (EDR = free) no papel, identificar árvore degenerada e explicar o Predecessor (maximo(r->esq)) na remoção com 2 filhos.
  • Árvores AVL: decorar vazia = -1, folha = 0, FB = esq - dir, detectar os 4 casos (sinais iguais = simples; sinais opostos = dupla) e lembrar que na inserção só rotaciona o 1º ancestral com |FB| ≥ 2 de baixo para cima.

⚡ Prioridade Rápida (Pontos Fáceis!)

  • Grafos: laço conta +2 no grau (grafo não direcionado) e vira 1 na diagonal da matriz; entrada vs saída no dígrafo; matriz simétrica vs lista de adjacência econômica.
  • Lista Dupla (LDE): saber por que insereFim/removeFim viram O(1) com ini e fim, religamento de nó no meio em O(1), e os 2 casos de borda (lista vazia → ini = fim = novo; remover único nó → ini = fim = NULL).

3. Checklist Anti-Pegadinha da Prova

🕸️ Grafos & Listas

  • Laço em grafo não direcionado: conta +2 no grau e coloca 1 na diagonal da matriz.
  • Matriz simétrica: só vale quando NÃO há setas; em dígrafo, M[A][B] = 1 não obriga M[B][A] = 1.
  • No** headRef na LSL: obrigatório quando a função pode trocar o 1º nó (head).
  • Remoção no fim da LSL: para no penúltimo nó (aux->prox->prox != NULL).
  • Destruição: salva atual->prox antes do free(atual) (evita use-after-free).
  • LDE vazia / nó único: inserir o 1º altera ini e fim; remover o único zera ini = fim = NULL.

🌳 Árvores ABB & AVL

  • Percursos: Pré (RED), In (ERD → sai ordenado na ABB!), Pós (EDR → apaga filhos antes do pai).
  • Remoção com 2 filhos na ABB: copia o Predecessor (maximo(r->esq)) e depois remove o nó original do predecessor!
  • Fórmula AVL dos slides: vazia = -1, folha = 0, FB = alt(esq) - alt(dir), válido se -1 ≤ FB ≤ 1.
  • Onde rotacionar na inserção AVL: apenas no 1º ancestral (subindo da folha p/ raiz) com |FB| ≥ 2!
